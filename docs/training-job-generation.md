# Phase 11 LlamaFactory job generation

Phase 11 creates a reviewable external training-job bundle; it does not execute training. Every job is department-scoped and starts from one exact succeeded, approved, unpurged Phase 10 dataset. `system_admin` and `department_admin` may enqueue, cancel, and review jobs only within their department. `system_admin`, `department_admin`, and `instructor` may read safe metadata. There is no cross-department bypass and no artifact, dataset, configuration, download, or raw-argument endpoint.

The fixed contract is LlamaFactory `0.9.5` with `Qwen/Qwen3-0.6B` at immutable revision `c1899de289a04d12100db370d81485cdf75e47ca`, Apache-2.0. The fixed profiles are `phase11-qwen3-0.6b-lora-v1` and `phase11-qwen3-0.6b-qlora-nf4-v1`. Both set `packing: false`, `neat_packing: false`, `enable_liger_kernel: false`, and `use_unsloth: false`, as well as SFT, `qwen3_nothink`, disabled thinking, a 8,192-token cutoff, deterministic seeds, and no remote code. QLoRA adds only reviewed NF4 four-bit settings: `quantization_bit: 4`, `quantization_method: bnb`, `quantization_type: nf4`, and `double_quantization: true`. `bnb` is the reviewed LlamaFactory enum value for its bitsandbytes backend; deprecated `use_liger_kernel` and `quantization_method: bitsandbytes` are never emitted. The normal worker never downloads or loads model/tokenizer bytes and CI does not install LlamaFactory. A parser compatibility smoke check is explicitly opt-in through `DEPTSLM_RUN_LLAMFACTORY_CONFIG_SMOKE=1` in a separately provisioned environment.

The immutable bundle is `manifest.json`, `training.yaml`, `dataset_info.json`, `train.jsonl`, and `validation.jsonl`. The parent retains exact verified Phase 10 file descriptors through final PostgreSQL authority; the child receives those descriptors directly and never reopens a source by pathname. Train and validation records are validated and copied through bounded buffers, while provenance is streamed only for identity and digest verification. Files are written only to private descriptor-relative staging, atomically renamed, and rehashed before PostgreSQL receives content-free digests, counts, contracts, lifecycle state, and review metadata. PostgreSQL and external storage are not transactional; only a committed succeeded job is authority for review. Reconciliation and retention purge are explicit, bounded, department-scoped operations. They group surfaces by exact publication attempt; job purge selects jobs, confirms every terminal attempt, and uses the rejection or archive timestamp under PostgreSQL server time. They clean only exact UUID attempt paths and never claim deletion from backups or audit history.

No question, instruction, answer, provenance, filename, path, model output, vector, training log, model weight, adapter, token, or credential is persisted in PostgreSQL, public responses, audit events, logs, or the browser. Phase 11 does not install or invoke LlamaFactory, run a scheduler, create training logs, produce adapters, promote a model, or implement Phase 12.
